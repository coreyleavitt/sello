# === sello-dev section (RFC-005 slice 7) ====================================
# The (Containerfile-hash, digest) drift pair for the `sello-dev` image
# (Containerfile at the repo root; scripts/test-libsodium.sh,
# scripts/bmc.sh, and later RFC-005 job wiring pull it by digest via
# scripts/lib/sello-dev-image.sh). "Rebuild and compare digests" is
# infeasible (container builds are not reproducible -- RFC-005 Part B, the
# sello-dev drift model paragraph); instead this line records the pair
# that was true at the last successful publish, and
# scripts/policy-lint.sh's sello-dev assertion fails if the CURRENT
# Containerfile's content hash no longer matches the recorded one -- the
# checkable proxy for "the Containerfile changed since the image
# recorded here was built," which is exactly the drift this check exists
# to catch (a Containerfile edit silently testing against a stale image).
#
# Format: three whitespace-separated fields --
#   `sello-dev <containerfile-sha256sum> <image>@sha256:<digest>`
# The second field is `sha256sum Containerfile`'s hex digest (the
# Containerfile as committed, not a build artifact of it). The third
# field is the published image's own manifest digest, in the same
# `image@sha256:...` form as the base-image section above --
# scripts/lib/sello-dev-image.sh's pull-by-digest reads this field
# directly.
#
# Repin ritual: after a Containerfile change, rebuild `sello-dev`, push it
# to ghcr.io/coreyleavitt/sello-dev by digest (see the image's own
# publish record in docs/rfc-005-validation-infra.handoff.md's slice 7
# entry for the exact push mechanism used), then update BOTH fields below
# together in the same commit as the Containerfile change -- never one
# without the other.
#
# Recorded 2026-08-24 (RFC-005 slice 7). NOT YET LIVE at ghcr.io: the
# real push is blocked on ghcr `write:packages` credentials at authoring
# time (no scope on the session's gh token, no podman ghcr.io login --

# exact, already-committed Containerfile and pushing the resulting image
