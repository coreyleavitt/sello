# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`sello` is a **pure-Nim Curve25519 library** (ed25519 EdDSA + X25519 ECDH) with **no FFI** in the core. It exists because the Nim ecosystem had no production pure-Nim 25519 — every other option wraps orlp's C. SHA-512 is the one dependency we do *not* reimplement; it comes from `nimcrypto`, resolved (not vendored) and pinned by commit SHA + content hash in `milpa.lock`. See `prompt.md` for the full design brief and rationale — it is the authoritative spec, and current code is a partial implementation of it.

## The load-bearing design decision: VERIFY is split from SIGN

This split drives the whole API and trust story — preserve it:

- **Verification** (`ed25519.verify`) touches only public data (pubkey, message, signature). It has **no constant-time requirement**, is fully testable, and is the part that ships to everyone with no asterisks. `scalarmultVartime` in `scalar.nim` uses plain 4-bit windows precisely because it only ever runs on the verify path — **do not add the signer's secret scalar to it**, and don't let it lose the `Vartime` suffix (RFC-001 finding 8: it used to be plain `scalarmult`, indistinguishable at call sites from the CT signer code sharing the file). `verify` has no backend dispatch and stays pure-Nim even under `-d:selloLibsodium`.
- **Signing / keygen** (`signing.nim` + `private/backend.nim`) holds the secret scalar → **is constant-time**: `{.push checks: off.}` cores, secrets confined to fixed-size stack arrays, every secret-dependent selection done by arithmetic masking (never a branch), and volatile-store-plus-barrier wiping (`private/ct.nim`) of every secret — including intermediate SHA-512 state — as soon as it's no longer needed. It carries the roll-your-own-crypto trust tax, backed by a dudect timing harness (`tests/ct/`, see below) and an **optional libsodium FFI adapter behind `-d:selloLibsodium`** (`private/backend_sodium.nim`) exposing the identical `Keypair` API.
- **X25519** (`x25519.nim`) also holds a secret (the caller's private scalar). Its Montgomery ladder is branchless on secret data (masked `feCSwap`, `{.push checks: off.}`, stack-only arrays, `private/ct.nim` wipe of the clamped scalar copy after use).

## Architecture (bottom-up layering)

`src/sello.nim` is the public facade — the supported API surface (`verify`, `x25519`, `x25519Base`, `x25519StaticSecret`, `x25519EphemeralSecret`, `keypair`, `sign`, `Seed`/`Keypair`/`toSeed`/`wipe`, and the nominal key/signature types `PublicKey`/`Signature`/`X25519StaticSecret`/`X25519EphemeralSecret`/`X25519Public`/`X25519Shared` plus their `toPublicKey`/`toSignature`/`toX25519StaticSecret`/`toX25519Public`/`toBytes` converters). Consumers `import sello`; submodules are importable but carry no stability promise.

Modules under `src/sello/`, each built strictly on the one(s) below (with one standing exception: `private/ct.nim` is a universal leaf that secret-holding modules at any position reach into directly, regardless of list order):

1. **`field.nim`** — GF(2²⁵⁵−19) arithmetic. Radix 2²⁵·⁵, 10 `int32` limbs (`Fe` object). Direct ref10/orlp port (public domain). All the `fe*` primitives: mul, sq, invert, `fePow22523`, encode/decode, canonicity check (`feBytesCanonical`), constant-time `feCMove`/`feCSwap`, and `clampScalar` (shared by ed25519 and X25519 clamping — lives here so `x25519.nim` stays a `field.nim`-only consumer).
2. **`wire.nim`** — leaf module (round-2 findings 27/28, split from the combined `types.nim` by RFC-002 slice 2 item 5): nominal wire types `PublicKey`/`Signature` (`distinct array[32/64, byte]`, RFC-001 finding 9) plus their `toPublicKey`/`toSignature`/`toBytes`/`==`/`$`/`hash` borrows — no crypto logic of its own, and (unlike the old combined module) no `private/ct` import either, since these types hold no secret to wipe. Relocated out of `scalar.nim`, which was holding these purely so `ed25519.nim` and `signing.nim` had a shared downward import; that polluted `scalar.nim`'s group-ops mandate with wire-format/hygiene concerns its arithmetic never touches. `ed25519.nim` (verify) and `signing.nim` (sign) both depend on `wire.nim` directly now; `ed25519.nim` still re-exports the types so `import sello/ed25519` alone finds them (preserved compatibility).
   **`wipe.nim`** — the other half of the old `types.nim` split (RFC-002 slice 2 item 5): the generic secret wipe `wipe*(var array[32, byte])` (RFC-001 finding 11), delegating to `sello/private/ct` (a leaf itself). `types.nim`'s own doc comment had admitted the wire types and this wipe shared that module for import-graph position only, not a common purpose ("two leftover leaf concerns, one roof"); splitting gives each its own single-purpose roof.
   **`challenge.nim`** — the ed25519 challenge hash `challenge(R, A, msg)` (RFC 8032 §5.1.6 step 4 / §5.1.7 step 2), extracted out of `scalar.nim` by RFC-002 slice 2 item 1: it was the one thing in that file pulling in nimcrypto's SHA-512. Imports `sello/scalar` (for `scReduce`) and `nimcrypto/sha2`; consumed by `ed25519.nim` (verify) and `private/backend.nim` (sign) — one audited copy of the formula shared by both, so sign/verify can never silently drift apart.
3. **`scalar.nim`** — Curve25519 group ops in extended Edwards coordinates (`GeP3`/`GeP2`/`GeP1P1`/`GeCached`). Point add/double, variable-base `scalarmultVartime` (verify-only, vartime — named with the suffix, RFC-001 finding 8, so it self-flags at every call site instead of relying on a doc comment to distinguish it from the CT signer code sharing this file), and fixed-base `geScalarmultBase` (signed radix-16 digits over a compile-time `GeCached` base table, CT `cmovCached` select — used by both keygen and signing, safe on secret scalars; a debug-only `assert` here checks its bit-255-clear precondition, wrapped in `when not defined(release)` so the dudect-measured build is untouched — plain `assert` alone does NOT get stripped by `-d:release` in this Nim 2.2.10 config, empirically verified, contrary to the RFC's stated assumption; see the assert's own comment). `scReduce`/`scIsCanonical`/`scMulAdd`/`pointEncode` also live here (moved down from `ed25519.nim` so the signing backend never imports the verify-only module); the shared `challenge(R, A, msg)` hash that used to live alongside them moved out to `challenge.nim` (above) in RFC-002 slice 2, taking this file's only nimcrypto import with it — `scalar.nim` is now a pure field-plus-curve-math leaf with no nimcrypto dependency. Curve constants (`Ed25519D_Raw`, `Ed25519Gx/Gy_Raw`, `SqrtM1_Raw`) live here too. `geSub` (dead ref10-port residue, zero call sites) was deleted in the same slice. Back to pure group ops as of round 2 — the wire types it used to hold moved to `wire.nim` (above).
4. **`ed25519.nim`** — RFC 8032 layer: `pointDecode` (strict §5.1.3: rejects y ≥ p and x=0-with-sign-bit) and `verify` (`openArray[byte]` and `string` overloads, taking the nominal `Signature`/`PublicKey` from `wire.nim`). Verify-only, never touches a secret, no backend dispatch — pure-Nim always, including under `-d:selloLibsodium`.
5. **`x25519.nim`** — RFC 7748 layer on `field.nim` only (no Edwards code): Montgomery ladder (branchless on the secret scalar, `private/ct.nim`-wiped after use), `x25519` (returns `none` on all-zero shared secret, i.e. small-order peer point) and `x25519Base`. Role-typed wrappers, one per X25519 role, not one type for all three (RFC-001 ledger #29, revisited on Corey's direction — supersedes finding 9's original one-`X25519Key` design), and the SECRET role is itself split in two (the X25519 static/ephemeral batch, closing the deferral this list used to record): `X25519StaticSecret` (a reusable private scalar; one-field object, not `distinct array`, for the same empirically-established reason `signing.Seed` isn't — see its doc comment — `=destroy`-wiped, deliberately copyable like `Seed`, every copy self-wipes independently), `X25519EphemeralSecret` (a SINGLE-USE private scalar, x25519-dalek's `EphemeralSecret` in this module's own vocabulary: move-only — `=copy {.error.}`, the `Keypair` pattern — constructed ONLY via `x25519EphemeralSecret()` (fresh from `std/sysrand`, no from-bytes route: freshness by construction), with NO `toBytes` either (unpersistable by design); `x25519Base(secret: X25519EphemeralSecret)` is a non-consuming plain-value borrow, `x25519(secret: sink X25519EphemeralSecret, peer)` CONSUMES it — `sink` plus the move-only `=copy` error together make reuse a compile error, fixture-verified (`tests/unit/fixtures/reject_ephemeral_reuse.nim`, `reject_ephemeral_copy.nim`, driven by subprocess `nim c` in `test_x25519.nim` — `compiles()`/`nim check` cannot see this error class, same reason as `Keypair`'s copy fixture) rather than a documented caller obligation), `X25519Public` (a public u-coordinate; plain `distinct array[32, byte]`, freely copyable, no destructor), and `X25519Shared` (a completed DH output; same shape as `X25519StaticSecret`, since it IS secret material). RFC 7748 does treat all three wire roles as the identical 32-byte format, and one type for all of them closed the cross-algorithm mixup (`verify(sig, msg, x25519Key)`) at zero ergonomics cost — but it also meant role confusion between secret and sendable X25519 material failed open, and gave no way to express "this secret must not outlive one exchange." Splitting the secret role further mirrors `Seed`/`PublicKey` on the ed25519 side for the sendable/secret boundary, and closes the single-use gap the same way `Keypair`'s move-only `=copy` closes accidental duplication. **Empirical Nim-ownership finding, load-bearing for the ephemeral design (verified via isolated scratch probes on Nim 2.2.10/ORC, not assumed):** the sink-argument "is this the last read" check is a simple per-symbol occurrence count over the whole scope, not an escape/alias analysis — ANY earlier reference to the same variable (even a bare field read or `addr`, confirmed directly), or the call merely sitting inside a `try`/`finally` (which `unittest.test` wraps every test body in), makes a later bare `x25519(secret, peer)` require a copy it cannot make; the caller must use `system.move` (`x25519(move(secret), peer)`, which needs `secret` declared `var`) whenever `x25519Base` (or anything else) touched the same variable first. A genuinely sole, un-annotated consuming call needs no `move()` — ordinary last-use inference already covers it (see `x25519.nim`'s doc comment on the `sink` overload for the full writeup, including the honest residual gap: `move()` is Nim's own explicit override of this analysis, so a caller who writes it at two separate consuming call sites for the same variable would compile — the natural, unadorned reuse pattern the negative fixtures actually cover remains correctly rejected). All types stay in `x25519.nim` rather than moving to `wire.nim`: they are RFC 7748's own types, with no consumer outside this module's own RFC 7748 layer, unlike `PublicKey`/`Signature`, which two separate upward modules needed to share. Also exports `toX25519StaticSecret`/`toX25519Public`/`toBytes`/`x25519StaticSecret()`/`x25519EphemeralSecret()` and the `X25519StaticSecret`/`X25519EphemeralSecret`/`X25519Shared`-typed `wipe` overloads (RFC-001 finding 11) that give callers holding X25519 secret material outside a `Keypair`/`Seed` a supported route to `private/ct.wipe`; the generic `array[32, byte]` `wipe` overload lives in `wipe.nim` (round-2 finding 28, its own leaf as of RFC-002 slice 2), not here, since it isn't X25519-specific.
6. **`signing.nim`** — `Seed`/`Keypair` types (fields private, move-only `Keypair`, `=destroy` wipes), the `keypair(seed)`/`keypair()` constructors, `sign`, and the `when defined(selloLibsodium)` backend dispatch (`private/backend_sodium` vs. `private/backend`, bound to one local name so every call site is backend-agnostic). Depends on `wire.nim` directly for `PublicKey`/`Signature` (not `ed25519.nim` — signing has no business importing the verify-only module; not `scalar.nim` either, since round 2 moved those types out of it). The facade re-exports from here with no conditional logic of its own.
7. **`private/backend.nim`** — the pure-Nim secret-math backend: seed-level `derivePublic`/`signDetached`, no `Keypair` knowledge. Builds on `field.nim` + `scalar.nim` + `challenge.nim` + nimcrypto SHA-512 only. Under `private/` because its exports bypass every `Keypair` guarantee (no invariant, no auto-wipe) — application code should use `sello.keypair`/`sello.sign`, never this module directly. `signDetached` carries a debug-only `assert` (RFC-002 slice 2) re-deriving and checking the caller-supplied public key against the secret scalar — expensive on purpose, wrapped in `when not defined(release)` (not a bare `assert`) so it is entirely absent from the dudect-measured/shipped release build.
8. **`private/backend_sodium.nim`** — the libsodium FFI adapter (only compiled under `-d:selloLibsodium`), mirroring `backend.nim`'s exact seed-level contract via `crypto_sign_seed_keypair`/`crypto_sign_detached`; atomic `sodium_init` once-guard (`std/atomics`, not a plain check-then-set flag).
9. **`private/ct.nim`** — the one audited secret-wipe primitive (`wipe[T]`: volatile per-byte stores + `asm volatile("" ::: "memory")` barrier, `{.noinline.}`), called from `backend.nim`, `x25519.nim`, `wipe.nim`, and `signing.nim`'s `Seed` destructor.

`tests/ct/` (`dudect.nim` + `ct_main.nim`) is the dudect-style timing harness, run via `scripts/ct.sh` — see below.

## Building & testing

**milpa** (Corey's Nim dependency resolver, `~/.local/bin/milpa`) is the authoritative resolver for development — not nimble. It reads `milpa.kdl`, clones deps into `_deps/` (content-addressed under `~/.cache/milpa`, gitignored), and writes `milpa.lock` (commit SHA + dag-sha256 content identity + provenance per dep — that's how nimcrypto is pinned; see NOTICE). Run `milpa fetch` once after cloning (and again after editing `milpa.kdl`) to populate `_deps/` and emit `nim.cfg`.

There is **no host Nim toolchain** in this environment; all builds happen in the base toolchain image. `scripts/test.sh`, `scripts/test-libsodium.sh`, and `scripts/ct.sh` (replacing the old nimble tasks) wrap the exact podman invocation, mounting the project plus the milpa CAS at both its canonical path and its host-absolute path (so milpa's absolute dep symlinks under `_deps/` resolve in-container).

`Containerfile.amox` is **amoxtli's sandbox image**, unrelated to sello (its package list — rust/go/node/openssl — belongs to a different project entirely); do not confuse the two or bolt sello-specific packages onto it. sello owns a minimal `Containerfile` of its own (`FROM ghcr.io/coreyleavitt/nim:2.2.10` + `libsodium-devel` + `z3-devel`), built as the `sello-dev` image and used by both `scripts/test-libsodium.sh` (libsodium adapter matrix) and `scripts/bmc.sh` (Z3-backed symex proof, RFC-001 finding 22) — one image covers both, rather than maintaining near-duplicate layers. `scripts/test.sh`, `scripts/ct.sh`, and `scripts/fuzz.sh` need neither this image nor network access.

**proptest** (property-based testing, RFC-001 finding 10) is an *optional* milpa dep: `milpa.kdl` declares it `optional=#true`, which milpa desugars into an auto-flag named `proptest` (default off) gating the dep — so `milpa fetch` alone (what a downstream consumer of sello runs) never fetches proptest or its own transitive deps (`nim-z3`, `softlink`; proptest's manifest depends on `nim-z3` unconditionally). To build/run the property tests, fetch it explicitly once: `milpa fetch --features proptest` (root-level `--features` flag, RFC #23 §3.4) — this populates `_deps/proptest`, `_deps/z3`, `_deps/softlink` and adds their `--path` lines to `nim.cfg`. `import proptest` compiles and links fine in the base image with no z3 shared library installed: the only proptest module that imports `z3` is `proptest/symex`, which the top-level `proptest` module never imports (confirmed empirically, not merely by reading the source). Re-running a plain `milpa fetch` afterwards prunes proptest back out (activation is recomputed from the manifest + requested features every fetch, not preserved from the lock) — this also means `milpa.lock`'s proptest/z3/softlink entries come and go with which fetch you last ran; that's expected, not a hygiene problem.

`milpa fetch` emits `nim.cfg` **wholesale** (`--path:"src"` + one `--path` per resolved dep) — it owns that file entirely and rewrites it on every fetch, so nothing else may live there. The project-standing `--mm:orc`/`--outdir:"build"` flags instead live in root `config.nims` (`switch("mm","orc")`, `switch("outdir","build")`), a file milpa never touches; Nim reads both `nim.cfg` and `config.nims` for every invocation, so the two compose without conflict. `build/` is gitignored — never commit binaries. `nim.cfg` and `_deps/` are also gitignored (regenerated by `milpa fetch`); `milpa.kdl` and `milpa.lock` ARE committed.

```sh
scripts/test.sh                          # full suite, pure-Nim backend
scripts/test-libsodium.sh                # same suite + interop tests, -d:selloLibsodium (needs the sello-dev Containerfile image)
scripts/ct.sh                            # tests/ct/ dudect timing harness, -d:release, ~1e6 samples/class (not part of test.sh)
scripts/fuzz.sh [seconds-per-target]     # tests/fuzz/ coverage-guided fuzzing (RFC-001 finding 12), default 60s x 3 targets
scripts/bmc.sh [timeout_secs]            # tests/verify/ Z3-backed symex proof (RFC-001 finding 22), default 300s hard kill-timeout (needs sello-dev)
scripts/check-readme.sh                  # nim check every ```nim fence in README.md — run after editing README examples (round-2 finding 24)
nim c -r tests/unit/test_field.nim       # one test module (after milpa fetch has populated _deps/ and nim.cfg)
```

`scripts/test.sh` and `scripts/test-libsodium.sh` both `source scripts/lib/unit-test-files.sh` for the `unit_test_files` bash array (round-2 finding 25 — this used to be two independently-typed-out copies of the same array, one per script, with a comment claiming they "cannot drift" despite nothing mechanically enforcing that; sourcing one file from both is what actually makes the claim true), replacing the old `sello.nimble` `unitTestFiles`/`runUnitTests` machinery deleted along with the nimble task layer.

All five `scripts/*.sh` entry points (`test.sh`, `test-libsodium.sh`, `ct.sh`, `fuzz.sh`, `bmc.sh`) `source scripts/lib/milpa-preflight.sh` and call `milpa_preflight` on the host before their podman invocation (RFC-001 ledger finding 30): a hard failure means `milpa.lock`/`_deps/` are genuinely out of sync (fix: `milpa fetch`, or `milpa fetch --features proptest`); no `milpa` binary on PATH warns and continues rather than failing an environment that doesn't have or need it; and — verified empirically, not assumed — a `FROZEN-ACTIVE-FLAGS-MISMATCH` result also warns-and-continues, because `milpa verify` (this milpa build, 0.0.1) takes no `--features` flag and always checks against the zero-feature default, so any host that has ever run the proptest-enabling fetch above trips that specific code on every subsequent plain `verify` even though nothing is actually stale. See the script's own header comment for the full reasoning.

- `tests/unit/test_wycheproof.nim`, `test_wycheproof_x25519.nim` — Google Wycheproof adversarial vectors (vendored in `tests/vectors/`, from C2SP/wycheproof `testvectors_v1`). These must stay at zero failures.
- `tests/unit/test_signing.nim` — RFC 8032 §7.1 keygen + sign vectors (incl. TEST-1024), sign→verify roundtrips, `Seed` destructor/wipe smoke tests.
- `tests/unit/test_ct.nim` — direct coverage of `private/ct.wipe` on both array and `Sha2Context` shapes.
- `tests/unit/test_facade.nim` — the full public surface is reachable through `import sello` alone.
- `tests/unit/test_libsodium_interop.nim` — bidirectional interop (pure sign/libsodium verify and vice versa); a no-op `skip()` under plain `scripts/test.sh`, real assertions only under `-d:selloLibsodium`.
- `tests/unit/test_properties_field.nim`, `test_properties_scalar.nim`, `test_properties_signing.nim` — property-based coverage (RFC-001 finding 10) via **proptest** (Corey's Hypothesis-style choice-sequence engine for Nim, `github.com/coreyleavitt/proptest`), an *optional* milpa dep (see "Building & testing" below for how it's enabled). Pins: field ring axioms (`feAdd`/`feMul` commutativity+associativity, distributivity, `feSub(a,a)==0`, `feMul(a, feInvert(a))==1`, `feNeg` involution) and `feFromBytes`/`feToBytes` roundtrips incl. near-p boundary stress (p-1, p, p+1..p+18, 2^255-1, all-zeros, all-0xFF) via canonical-encoding comparison, never raw limbs; `feCMove`/`feCSwap` both flag values; `scReduce` idempotence + boundary inputs (0, L-1, L, L+1, 2^512-1) + output-always-canonical; `recodeScalarRadix16` reconstruction (Σ digits[i]·16^i == s) against a tiny independent bignum oracle, over both the clamped and reduced-mod-L scalar domains; `geScalarmultBase` vs `scalarmultVartime` agreement (generalizing test_scalar.nim's fixed-sample standing guard) plus a `geScalarmultBase` additivity-over-`scMulAdd` group-law check; sign→verify roundtrip and single-bit-flip rejection (signature and message) on random seeds/messages.
- `tests/ct/` — dudect-style timing harness (`scripts/ct.sh`, separate from `scripts/test.sh`); results in `docs/ct-results.md`.
- `tests/fuzz/` (`fuzz_common.nim` + `fuzz_main.nim`) — coverage-guided fuzzing (RFC-001 finding 12) of the attacker-controlled-input surface ONLY: `ed25519.pointDecode`, `ed25519.verify`, and `x25519` over the peer's public u-coordinate. Uses **proptest**'s in-process `fuzzWith` (IR mutation mode); coverage signal comes from `{.cover.}`-instrumented wrapper procs local to the harness, not from sello's own source (kept untouched). Deliberately excludes `backend.signDetached`/`scalar.geScalarmultBase` (the secret-scalar signing path) — that's branchless by construction and its risk is a timing side channel, which `tests/ct/`'s dudect harness owns, not a mutation fuzzer's. Run via `scripts/fuzz.sh`; separate from `scripts/test.sh` (open-ended campaign, not a fixed pass/fail suite).
- `tests/verify/` (`symex_recode.nim`) — machine-checked (Z3, via **proptest**'s `proptest/symex`) proof of `scalar.recodeScalarRadix16`'s digit-range invariant (RFC-001 finding 22). **Honest scope**: a full whole-function, whole-input-domain symbolic execution was attempted and did not complete (killed after a 300s budget, resource exhaustion — not a proof of infeasibility); what actually runs and completes (~sub-second Z3 time) is the **per-iteration inductive lemma** the loop's own carry-propagation step must satisfy (nibble in [0,15] + carry-in in {0,1} ⇒ digit in [-8,7] + carry-out in {0,1}, plus the tighter bit-255-clear-bounded final-digit case), exhaustively decided by Z3, not sampled. The 63-step composition (induction: carry starts at 0 ∈ {0,1}, each step's postcondition is the next step's precondition) is a manual argument in the harness's module doc comment, not itself a single Z3-checked artifact. The reconstruction identity (Σ digits[i]·16^i == s) stays sampled (`test_properties_scalar.nim`), not attempted symbolically (symex's integer model tops out at machine-width ints; a faithful 256-bit encoding was judged not worth the engineering cost given the sampled coverage already in place). Run via `scripts/bmc.sh`; needs the `sello-dev` image (z3-devel) and a hard external kill-timeout (Z3 queries can hang — see the harness's own module doc comment).

### The validation bar (what earns trust without an audit)
This is the project's whole reason for caution — hold new code to it:
- Bit-exact pass of **RFC 8032** (ed25519) and **RFC 7748** (X25519) vectors. ✅ enforced in CI-less reality by `scripts/test.sh`.
- Pass **Google Wycheproof** adversarial vectors — the verifier must reject every malleable/non-canonical/small-order forgery. ✅ `test_wycheproof*.nim`.
- A **dudect/ctgrind-style timing harness** for the signer. ✅ `tests/ct/`, `scripts/ct.sh` — clean pass on all three secret-holding targets (`signDetached`, `geScalarmultBase`, `x25519Base`); honest environment caveats (container not bare-metal, `powersave` not `performance`) recorded in `docs/ct-results.md`.
- **Property-based testing** of the field/scalar primitives that RFC/Wycheproof vectors only exercise transitively (ring axioms, roundtrips, `scReduce` idempotence, recoding reconstruction, `geScalarmultBase` group-law agreement, sign/verify bit-flip rejection). ✅ `test_properties_*.nim` via **proptest** (optional milpa dep — see "Building & testing").
- **Coverage-guided fuzzing** of the attacker-controlled-input surface (`pointDecode`, `verify`, `x25519`'s peer u-coordinate) for crash/exception freedom. ✅ `tests/fuzz/`, `scripts/fuzz.sh`, via proptest's `fuzzWith`. Scope: verify/decode-path inputs only, never the secret-scalar signing path (that's dudect's job).

## Conventions
